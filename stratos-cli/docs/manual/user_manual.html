1. About this manual and the CLI

The Stratos CLI (command name stratos) is a command-line tool that lets a developer or team lead do, from one terminal, the routine work of the Stratos developer platform:

  • sign in through the company identity provider;
  • create and manage projects and GitHub repositories to company standards;
  • set up any folder for AI-assisted development (Claude Code instructions, skills, tool servers, knowledge);
  • provision personal workspaces;
  • manage environments and request deployments and rollbacks;
  • ask AI models questions, run AI agents, and search organisational knowledge;
  • review the audit trail, and check the health of your setup (doctor).

1.1 Important facts to know up front

There is no Stratos Platform API yet. Where GitHub already has the concept, Stratos uses GitHub (repositories, branch protection, environments, deployments). Projects and workspaces are recorded in files on your own computer. Some things you might expect to be central (for example a company-wide list of projects) are therefore per machine for now.
Stratos never bypasses permissions. It uses your identity for Stratos permissions and your GitHub token for GitHub permissions. If GitHub says no, Stratos cannot say yes.
Deployments are requested, not performed. stratos deploy asks GitHub for a deployment and marks it queued. Your project's own automation (CI) does the actual rollout and reports the real result.
Secrets are never stored in plain text. Sign-in tokens live in your operating system's secure store (Windows Credential Manager, macOS Keychain, Linux Secret Service). API keys are read from environment variables. Configuration files hold only names of variables, never values.

3. Installation

Which way should I install?
• Most users: install with npm (section 3.7). One command; no environment to activate.
• Contributors and people changing the code: install from the source folder (3.1 and 3.2).
• No repository or npm access: install the wheel file (3.4).

3.1 From the source folder (development / first use)

Open a terminal in the stratos-cli folder and run:

python scripts/bootstrap.py

This creates a private Python environment in .venv, installs Stratos and its tools, and prints the version. The "pip new release" notice is harmless.

3.2 Activate the environment (source installs only; every new terminal)

Installed with npm (3.7)? Skip this step: nothing needs activating.

The bootstrap installs stratos inside .venv. Until you activate it, your terminal does not know the command and shows "'stratos' is not recognized" (Windows) or "command not found" (macOS/Linux).

TerminalCommand
Windows Command Prompt.venv\Scripts\activate
Windows PowerShell.venv\Scripts\Activate.ps1
If blocked ("running scripts is disabled"): Set-ExecutionPolicy -Scope Process RemoteSigned, then retry.
Git Bashsource .venv/Scripts/activate
macOS / Linuxsource .venv/bin/activate

When active, your prompt starts with (.venv). Check with:

stratos --version
stratos 0.1.0
Without activating: run .venv\Scripts\stratos --version (Windows) or .venv/bin/stratos --version (macOS/Linux), or .venv\Scripts\python -m stratos --version.

3.7 Install with npm (recommended for most users)

The npm package installs the Stratos CLI for you. It contains the CLI, and while installing it creates a private Python environment inside the package, so your own Python is not changed. After installation the stratos command works in every terminal: there is no environment to activate.

Requirements

  • Node.js 18 or newer (includes npm). Check: node --version.
  • Python 3.12 or newer on your PATH. Check: python --version (on Windows py -3.12 --version also works). On Windows, tick "Add python.exe to PATH" when installing Python.
  • Internet access during installation (the Python libraries are downloaded once). Behind a proxy, set HTTPS_PROXY first (10.3).
  • About 150 MB of disk space.

Install

One-time setup: tell npm where the package lives. The package is published on the company's GitHub Packages registry, which asks you to sign in even though the package itself is not secret.

  1. In GitHub open Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token. Tick only read:packages. If your organisation uses single sign-on, click Configure SSO → Authorize next to the token. Copy the token.
  2. Run these two commands (replace YOUR_GITHUB_TOKEN with the token):
npm config set @stratos-technologies-fzco:registry https://npm.pkg.github.com
npm config set //npm.pkg.github.com/:_authToken YOUR_GITHUB_TOKEN

The token is saved in your personal npm settings file (.npmrc in your home folder). Do not share it or commit it. Do this once per computer; only packages under the @stratos-technologies-fzco name use this registry.

Install:

npm install -g @stratos-technologies-fzco/stratos-cli
stratos --version
stratos 0.1.0

From a package file you were given (stratos-technologies-fzco-stratos-cli-0.1.0.tgz):

npm install -g C:\path\to\stratos-technologies-fzco-stratos-cli-0.1.0.tgz

Installation takes a few minutes (the log shows "creating a private Python environment" and "installing"). Wait for it to finish. The final line is "Stratos CLI is ready. Try: stratos --version".

Then

Continue with section 4 (first-time setup). Everything after installation is identical to any other installation method.

4. First-time setup

Do these steps once per computer.

4.1 Check your machine

stratos doctor

Read section 13.5 to understand each line. At this point "Sign-in configured" and "GitHub credentials" will probably warn; the next steps fix them.

4.2 Tell Stratos about your identity provider

You need two values from your company's identity provider (Microsoft Entra ID, Okta, Auth0, Keycloak, and similar). Ask your IT/security team:

  1. Issuer URL, for example https://login.microsoftonline.com/TENANT-ID/v2.0 or https://yourcompany.okta.com. It must start with https:// (plain http only for localhost).
  2. Client ID of an application registered for the CLI.
stratos config set auth.issuer https://yourcompany.okta.com
stratos config set auth.client_id 0oa1b2c3d4e5f6g7h8i9

The client ID is not a secret. Never put a client secret anywhere: the CLI uses a public-client sign-in (Authorization Code with PKCE) that needs none.

For administrators: how the application must be registered

SettingValue
Application typePublic / native client
GrantAuthorization Code with PKCE (no client secret)
Redirect URIhttp://127.0.0.1/callback. The CLI opens a temporary listener on a random free port on the local machine only, so the provider must accept a loopback address with any port (some need http://127.0.0.1:*/callback).
Scopesopenid profile email offline_access (change with auth.scopes)
DiscoveryISSUER/.well-known/openid-configuration must be reachable and list an authorisation and token endpoint
RolesThe user's token or profile must carry a roles or groups claim containing viewer, developer, maintainer or admin. Users with no recognised role are treated as viewer.

4.3 Give Stratos your GitHub access

Choose one:

gh auth login                     (GitHub CLI; recommended)

or set a personal access token in the environment (see 10.3 for how to set variables on each system):

GITHUB_TOKEN=ghp_yourtokenhere

The token needs rights to the organisation's repositories (typically repo and, for environments and deployments, admin rights on the repository).

4.4 Set your organisation (if not the default)

stratos config set github.organization YOUR-GITHUB-ORG

The default is Stratos-Technologies-fzco. Any command with --org overrides it for one run.

4.5 Optional: AI provider

stratos config set ai.provider claude          (claude | openai | azure-openai)
stratos config set ai.model claude-sonnet-5
ANTHROPIC_API_KEY=...                           (or OPENAI_API_KEY / AZURE_OPENAI_API_KEY)
stratos ai status

For Azure OpenAI also set ai.azure_endpoint.

4.6 Sign in and confirm

stratos login
stratos whoami
stratos doctor

5. Signing in and out

5.1 Sign in

stratos login
  1. Stratos opens your web browser at your identity provider.
  2. Sign in as you normally do (including any multi-factor step).
  3. The browser shows a success page and returns to the terminal, which prints your name and organisation.

Your tokens are stored in the OS secure store, not in a file. The session refreshes itself when possible.

No browser available (remote server, SSH, container)

stratos login --no-browser

Stratos prints the sign-in address. Open it on a computer that has a browser. Note that the redirect returns to 127.0.0.1 on the machine where Stratos runs, so this works when you can reach that port (for example through port forwarding), not from an unrelated computer.

5.2 Who am I, and am I still signed in?

stratos whoami          identity and roles
stratos auth status     session state (local check; tokens are never shown)

5.3 Use the token in a script

stratos auth token            shows a masked token
stratos auth token --reveal   prints the full token (treat it like a password)

5.4 Sign out

stratos logout

Removes stored credentials from this computer.

5.5 Sign-in problems

Sign-in is not configured.Set auth.issuer and auth.client_id (4.2).
Cannot reach the identity provider: ...Network, VPN or proxy issue, or wrong issuer URL. Open the issuer URL plus /.well-known/openid-configuration in a browser; it should show JSON.
Issuer discovery document is missing 'KEY'.The issuer URL is not an OpenID Connect issuer, or has an extra path. Ask IT for the exact issuer string.

6. How commands work

6.1 Shape of a command

stratos [GLOBAL OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]

Global options come before the command name. Example: stratos -o json repo list (not stratos repo list -o json).

Get help anywhere: stratos --help, stratos repo --help, stratos repo create --help.

6.2 Global options

OptionMeaning
--versionPrint the version and exit.
--verboseShow informational log messages.
--debugShow debug logging and full error details (tracebacks). Use this when reporting a problem.
--output, -oOutput format: table (default, for people), json (for scripts), yaml, plain (simple text) or quiet (minimal output).

6.3 Safety switches available on most changing commands

OptionMeaning
--dry-runShow exactly what would happen; change nothing. Use it first on anything unfamiliar.
--yes, -yDo not ask for confirmation (for scripts). Destructive actions otherwise ask first, and answering no cancels with exit code 10.

6.4 Commands that repeat safely

These can be run again after a failure or interruption: project create, init, repo create, environment create, workspace create. They skip what already exists and finish what is missing.

6.5 Output for scripts

stratos -o json repo list
stratos -o json whoami

Long values are never wrapped or cut in JSON. In table mode narrow terminals may shorten cells; widen the window or use -o json.

6.6 Exit codes

Every run ends with a number. 0 means success; anything else means something to fix. Scripts should test it (echo %ERRORLEVEL% on Windows cmd, $LASTEXITCODE in PowerShell, $? or $status in shells).

CodeMeaningFirst thing to try
0Success-
1General error (unexpected)Re-run with --debug; see 15
2Invalid usage (bad command line)Check spelling; stratos COMMAND --help
3Authentication failurestratos login; set the GitHub/AI credential
4Authorisation failure (role or policy)stratos whoami; ask for a role; stratos org policy
5Not foundCheck the name with the matching list command
6Validation failure (bad input)Fix the value the message names
7Network or API errorCheck connection, VPN, proxy; retry
8Configuration errorstratos config list; fix the setting named
9Missing dependencyInstall the tool named; stratos doctor
10CancelledYou answered no or pressed Ctrl+C; nothing was changed

6.7 Errors are readable on purpose

Normal failures show a plain sentence and often a hint line saying what to do. Technical stack traces appear only with --debug (or environment variable STRATOS_DEBUG=1). Secrets are masked in all messages and logs.

7.1 "You do not have permission for 'x'"

  1. Run stratos whoami to see your roles.
  2. Find permission x in the table above to see which role is needed.
  3. Ask an administrator to add the role in the identity provider, then stratos logout and stratos login so the new role is picked up.

8.7 Setting up an existing folder: stratos init

stratos init [--name NAME] [--template python|node|none] [--skill S] [--mcp M] [--dry-run] [--diff] [--yes]

Run inside the folder. It detects what is already there (Python or Node), adds only what is missing, keeps existing content, backs up any file it changes, and undoes everything if a step fails. Running it twice changes nothing the second time. It creates or updates:

CLAUDE.mdOrganisation instructions inside a managed block. Your own text outside the block is never touched.
.claude/settings.jsonAdds rules that stop Claude Code reading .env secret files. Your existing rules are kept.
.claude/skills/, .mcp.jsonOnly if you pass --skill / --mcp.
.gitignoreAdds lines that keep secrets and local files out of git.
.github/workflows/ci.ymlStarter pipeline for the chosen template (not overwritten if present).

Always preview the first time: stratos init --dry-run --diff.

8.9 Environments and deployments

Environments are GitHub Environments of the project's repository. Names: development (alias dev), staging, production.

9. Step-by-step workflows

9.1 Start a brand-new project

stratos whoami                                   (need developer role or higher)
stratos project create my-app --template python --owner @my-org/platform-team --dry-run
stratos project create my-app --template python --owner @my-org/platform-team
stratos project get my-app                       (status should be "active")
stratos workspace create my-app-dev --project my-app --python
stratos workspace connect my-app-dev             (tells you how to enter the folder)

If project create is interrupted: stratos project get my-app shows partial and the error; fix the cause; run the same project create again.

9.2 Bring an existing folder into the standard setup

cd path\to\folder
stratos init --dry-run --diff
stratos init
stratos doctor

Changed your mind? stratos backup list, then stratos backup restore ID.

9.3 Ship a change

stratos environment list --project my-app
stratos deploy dev --project my-app --ref my-feature-branch
stratos deploy status --project my-app -e development
stratos deploy staging --project my-app
stratos deploy production --project my-app --dry-run
stratos deploy production --project my-app       (asks to confirm)

9.4 Roll back a bad release (maintainer or admin)

stratos deploy status --project my-app -e production
stratos deploy rollback -e production --project my-app --dry-run
stratos deploy rollback -e production --project my-app

To go to a specific known-good deployment: --to DEPLOYMENT-ID.

9.5 Add a skill and a tool server to a project

stratos config set skills.registry C:\company\skills          (folder that contains index.json)
stratos config set mcp.registry C:\company\mcp
stratos skill list
stratos skill install code-review
stratos mcp list
stratos mcp install github-tools
stratos mcp configure github-tools --env GITHUB_TOKEN=GITHUB_TOKEN
stratos mcp status

Names above are examples; use the names shown by skill list and mcp list.

9.6 Search company knowledge and connect it to Claude Code

stratos config set knowledge.paths C:\company\docs
stratos knowledge sync
stratos knowledge search "release checklist"
stratos knowledge connect --dry-run
stratos knowledge connect

9.7 Weekly audit review (maintainer or admin)

stratos audit summary --days 7
stratos audit list --limit 100
stratos -o json audit list --action deployment.create

9.8 Use Stratos in automation (CI or scripts)

set STRATOS_AUTH__ISSUER=...            (settings via environment, see 10.2)
set GITHUB_TOKEN=...                    (credential from the CI secret store)
stratos -o json project list
if %ERRORLEVEL% neq 0 exit /b %ERRORLEVEL%
stratos deploy dev --project my-app --yes

Always use --yes for changing commands in automation (nothing can answer a prompt) and check the exit code.

10. Configuration reference

10.1 Where settings come from (highest priority first)

  1. Command-line options (for example --org)
  2. Environment variables (STRATOS_...)
  3. Project file: .stratos/config.yaml in the current folder
  4. User file: config.yaml in your user configuration folder (11)
  5. Organisation file: config.yaml in the system-wide configuration folder (set by administrators; use for policy)

12. Safety features: dry run, backups, rollback, audit

12.1 Dry run

--dry-run runs the same logic as the real command but writes nothing and contacts GitHub only to read. The output lists each planned change (and a diff for files). Dry run performs the permission checks, so it also tells you whether you are allowed to do the real thing.

12.2 Automatic backups

Before Stratos changes or removes a file you may already own (CLAUDE.md, .mcp.json, .claude/settings.json, a skill folder, ...) it saves a copy in .stratos/backups/. Restore with:

stratos backup list
stratos backup restore ID --dry-run
stratos backup restore ID

ID is the value in the id column of backup list (or the backup file name). If it matches more than one, use the full id. Restoring a removed skill refuses to overwrite a skill folder that exists; remove it first.

12.3 All-or-nothing changes

init and skill install treat their steps as one unit. If any step fails, earlier writes are rolled back and the folder is left as it was. project create works differently on purpose: it never deletes what it built; it records progress so the same command resumes.

12.4 Managed blocks and merging

In files shared with you (CLAUDE.md) Stratos writes only between its own marker lines. In JSON files it merges keys and never removes yours. Do not edit inside the markers; edit anywhere else freely.

12.5 Audit trail

Sensitive actions (create, delete, deploy, rollback, install, restore, and denied attempts) are recorded with time, user, action, target and result. Secrets are masked. Maintainers and admins read it with stratos audit .... The file is local until a platform service exists (11.1).

If the audit log cannot be written ("The audit log cannot be written: ..."), the action is stopped rather than done unrecorded. Free disk space or fix folder permissions.

13. Troubleshooting

13.1 Five-minute diagnosis

  1. Is the environment active? Prompt should start with (.venv); stratos --version should work (3.2).
  2. Run stratos doctor. Fix anything marked fail, then warn items relevant to what you are doing (13.5).
  3. Read the message and the hint line. Look the message up in 13.4, or the exit code in 13.3.
  4. See what settings are in effect: stratos config list. An environment variable may be overriding your file (10.1).
  5. Re-run with --debug to see details, and with --dry-run to test without changing anything.
  6. Still stuck? Follow section 15 to collect the right information.

13.6 Network problems (exit code 7)

  1. Can you open https://api.github.com and your identity provider address in a browser on the same computer?
  2. On a company network, connect the VPN if required.
  3. Behind a proxy set HTTPS_PROXY (and HTTP_PROXY) in the environment (10.3). The standard proxy variables are honoured by the HTTP library. Ask IT for the address.
  4. TLS/certificate errors on company networks usually come from an inspecting proxy; ask IT for the company root certificate and how to register it for Python.
  5. Rate limits (HTTP 429) are retried automatically with the wait GitHub asks for. If it still fails, wait a few minutes.
  6. Run stratos doctor --online to see which service is unreachable.

13.7 "No secure credential store is available"

Stratos refuses to keep sign-in tokens in a plain file. It needs an OS keyring.

SystemFix
WindowsUses Credential Manager: normally present. Make sure you are running as a normal signed-in user (not a locked-down service account).
macOSUses Keychain. Unlock the login keychain; allow the prompt.
Linux desktopInstall and unlock a Secret Service provider (GNOME Keyring or KWallet), for example sudo apt install gnome-keyring, then log in again.
Linux server, container, WSL, CIThere is usually no keyring. Interactive sign-in cannot store tokens there. Use a machine with a keyring, or use automation credentials through environment variables.

13.8 GitHub access problems

  1. stratos doctor: "GitHub credentials" must pass.
  2. If you use a personal token, make sure it has not expired and that the organisation approved it (SAML single sign-on organisations require you to authorise the token).
  3. 403 or "Must have admin rights": your GitHub account needs a higher role on that repository or organisation.
  4. 404 for a repository you know exists: usually no access. GitHub hides repositories you cannot see.
  5. Some features (environment protection rules, some security settings) need a paid GitHub plan.

13.9 A deployment stays "queued"

This is expected until your project's CI acts. Stratos only requests the deployment. Your pipeline must trigger on GitHub deployment events and report statuses (in progress, success, failure). Check stratos repo workflows PROJECT and stratos repo runs PROJECT. Stratos never marks a deployment successful itself.

13.10 A project shows "partial"

  1. stratos project get NAME: read last_error.
  2. Fix the cause (permissions, name clash, network, policy).
  3. Run the same stratos project create NAME ... again. Completed steps are skipped; the repository is never duplicated.

13.11 I made a change I did not want

  • File changed by Stratos: stratos backup list, then stratos backup restore ID.
  • Skill removed by mistake: restore its backup, or stratos skill install NAME again.
  • Wrong deployment: stratos deploy rollback (9.4).
  • Repository archived: unarchive it in GitHub (no Stratos command yet).
  • Project record deleted: the repository still exists; run stratos project create NAME to re-register (existing repository is reused).

13.12 Speed and disk

  • stratos --help is fast because commands load only when used. The first use of a command in a session may take a moment.
  • Slow lookups: metadata is cached briefly; stratos cache status shows it. --refresh forces fresh data.
  • Cache growing: stratos cache prune or clear.

14. Frequently asked questions

Do I need to be online? For sign-in, GitHub and AI features, yes. doctor, status, config, version, backup, cache and init --dry-run work offline.

Is it safe to run project create twice? Yes. It resumes and never duplicates the repository.

Can I undo stratos init? Yes: stratos backup list and stratos backup restore. Files that did not exist before (for example a new .stratos folder) can simply be deleted.

Where are my passwords or tokens stored? Sign-in tokens: OS secure store only. API keys: your environment only. Never in Stratos files, logs, cache or audit.

Why does Stratos ask me to confirm? It confirms destructive or production actions. Use --dry-run to preview and --yes to skip the question in scripts.

Why does deploy production succeed but nothing changes? The deployment is only requested (13.9).

Can two people share one project registry? Not yet: the registry is per computer until the Platform API exists. GitHub itself is shared.

Why is a public repository refused? Organisation policy (policy.allow_public_repos is false).

Can I use it on GitHub Enterprise Server? Set github.api_url to your server's API address.

How do I use a different organisation for one command? --org OTHER-ORG.

I changed roles at the identity provider but nothing changed. Sign out and in again (stratos logout, stratos login).

How do I see exactly what happened earlier? stratos audit list (maintainer or admin), or your file backups with stratos backup list.

How do I update Stratos? Installed with npm: npm install -g @stratos-technologies-fzco/stratos-cli@latest (3.7). Installed from source: get the newer source and re-run python scripts/bootstrap.py (3.5).

Can I install it with npm install? Yes: see 3.7. It needs Node.js 18+ and Python 3.12+ on the computer.
